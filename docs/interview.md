# 面试准备

| 问题 | 应答要点 |
|---|---|
| Topic、Service、Action 怎么选？ | 关节反馈是连续数据，用 Topic。查询状态等短请求用 Service。轨迹执行耗时且需要反馈、结果和取消，用 Action。 |
| TF、URDF、SRDF、控制器配置分别是什么？ | TF 保存坐标系关系；URDF 描述几何与关节；SRDF 描述规划语义；控制器配置定义实际执行接口。 |
| FK、IK、路径、轨迹的区别？ | FK 将关节角映到末端位姿，IK 反求可能的关节解。路径主要是几何序列，时间参数化后才是可按时间执行的轨迹。 |
| 为什么要 executor？ | 状态订阅与 Action、Service 回调需要被处理。工作线程等待规划结果时，独立 spin 可继续处理消息。 |
| RRTConnect 与 RRT* 有何区别？ | RRTConnect 双向扩展尝试快速连起起点和目标；RRT* 随采样增加改善路径代价，有限预算下的实际效果靠实测。 |
| Pilz LIN 为什么会在有可绕障路线时失败？ | LIN 规定笛卡尔直线路径。直线被遮挡或关节限制不满足时应失败。自由路径允许改变空间路线。 |
| 为什么规划成功、执行却失败？ | 规划和控制器执行有不同条件。检查控制器 active、动作名、目标发送、起始状态、轨迹时间、sim time、反馈和容差。 |
| 如何体现 C++ 工程能力？ | 读一个自己写的函数，讲输入、错误处理、生命周期及一个调试例子。明确哪一段复用了原库。 |
| 你如何比较规划器并解释末端误差？ | 同问题同预算分别看规划率和执行率。误差读统一坐标系的执行后状态。路径指标与控制跟踪误差分开。 |
| 规划失败和动态重规划有什么区别？ | 未执行的计划失败时可重试；动起来以后还需取消、确认状态、更新场景以及重新校验轨迹。 |

## 90 秒讲述练习

准备五句话。任务是什么，你改了什么，如何控制变量，结果在哪个 CSV 或视频能证实，哪些现象还不能下结论。再把一次失败的日志、源码和修复后结果连起来。当前项目启动材料与未来的实测结果分别表述。
