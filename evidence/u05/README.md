# U05 · UR5e 工位碰撞检查与绕障规划

2026 年 11 月 27 日在本机 Ubuntu 24.04、ROS 2 Jazzy、Gazebo Harmonic 和 MoveIt 2 上完成。本记录整理自实测终端输出。此前的控制器联调、关节反馈、C++ 规划与执行以及末端误差见 [U02–U04 记录](../u03-u04/README.md)。

## 工位与测试条件

- 自建工作台、A/B 料箱和后护栏，在 MoveIt 规划场景中加入对应碰撞体。RViz 界面记录了盒口挡板用例的目标连杆标红和规划失败，交互期间出现闪退。后续由 C++ 节点发起固定 B 盒目标的规划，用 ROS 2 服务验证中途障碍碰撞。
- B 盒上方目标为 `world` 中 `tool0` 的位置 `(0.57, 0.23, 0.48) m`，四元数 `(x, y, z, w) = (1, 0, 0, 0)`。调用 `/compute_ik` 并启用 `avoid_collisions`，返回 `val=1`。
- 以启动节点时的当前关节反馈为起点。对照日志中的 `shoulder_pan_joint` 起点均为 `0.000000 rad`。C++ 使用 OMPL，B 盒目标的规划预算为 `5 s`，各轮均以 `execute_motion:=false` 运行。
- 中途障碍物 `bin_b_path_blocker` 是 MoveIt 场景内的 `0.08 × 0.08 × 0.08 m` 方块，`world` 中的中心为 `(0.0091, 0.2046, 0.7226) m`。

## 固定目标及原路径检查

将逆解按关节名写入规划组。原始角度组的无挡板规划返回 `99999`。对其中四个关节加减 `2π` 后，末端目标位姿等价。后续对照使用下表中的目标关节角。原轨迹的前臂中心由索引 `44` 处的正运动学求出，用于定位测试方块。

| 关节 | 固定目标（rad） | 原轨迹索引 44（rad） |
| --- | ---: | ---: |
| `shoulder_pan_joint` | -2.5394589968293775 | -1.283604669258 |
| `shoulder_lift_joint` | -1.8281521935821416 | -1.700485100609 |
| `elbow_joint` | -1.2978957619345404 | -0.656013082313 |
| `wrist_1_joint` | -1.5863402852232849 | -1.578306437309 |
| `wrist_2_joint` | 1.5707964369807978 | 0.794005498786 |
| `wrist_3_joint` | -0.968662609966626 | -0.489614817371 |

在加入方块后调用 `/check_state_validity`，当前起点和固定目标均返回 `valid=True`。将原轨迹索引 `44` 处的关节角传入同一服务，返回 `valid=False`，碰撞对为 `forearm_link` 和 `bin_b_path_blocker`。

带挡板的第二次请求生成了通往同一目标的新轨迹。其索引 `54` 处的前臂中心坐标为 `(-0.1260, 0.2906, 0.6000) m`。上述结果用来验证该工位的规划流程，表中分别保留了首次失败和复跑成功。失败原因尚待进一步定位。

## 验收范围

- 已验证可达基线、指定障碍阻断旧轨迹的中间状态、起终点在场景更新后有效，以及同一目标下的带障碍规划成功。
- 待补独立的不可达目标用例与轨迹未下发记录，以及新轨迹第 54 号状态的单独碰撞抽查。本轮为纯规划测试。
- 原始日志与带 `use_bin_b_goal` 开关和 `probe` 输出的实验源码保存在实验 Ubuntu 工作区。本页归档实测结果与复跑所需的关键输入。运行中出现的 URDF/SRDF 名称差异和客户端 IK 配置提示留待联调时核对。
